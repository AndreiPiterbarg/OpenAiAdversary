The presentation closely follows figure 04 of [Linear's agent activity](https://linear.app/developers/aig): muted narration above a compact action row, small filled action symbols, inline metadata and a disclosure triangle, and a 6×6 animated dot-matrix working indicator. There are no numbered stage headers, connecting rails, agent badges, or session cards. Leading explanations stay visible as actions accumulate; opening an action reveals its code, comparisons, boundary notes or finding. CSS animates disclosures and newly arrived actions. The viewport follows newly arrived activity only in Follow live mode, after expansion settles. Reduced motion disables these transitions.

Typing uses elapsed time from [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame), so display refresh rate does not determine its speed. A [step-end caret animation](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/easing-function/steps) supplies the terminal cursor; no animation dependency is needed.

## Results

The user selected Sentry's issue-detail hierarchy in dark mode after reviewing the references in `frontend/docs/research/results-design-references.md`. `/demo/results` opens directly on the first finding; the Findings selector exposes all three supplied cases immediately. An unboxed issue header and compact toolbar flow into an event-detail panel and a separated context sidebar. The page has no enclosing card; borders are reserved for evidence and internal separators. Each detail begins with the failure, repository and attack channel, then explains the task and changed condition. Without attack / With attack tabs retain both outcome summaries and show the selected arm's full observed output in one wide code frame. The failing arm is selected initially. Repository context and attack code expand independently as grouped source frames, with line numbers, restrained token colors, and pass/fail line highlights. Jump links open the relevant evidence section. The selector, adjacent-finding arrows, and related findings provide access to every case. A narrow metadata column identifies the models, unavailable follow-up checks, and the supplied failure mechanism. There are no aggregate charts, severity rankings, timestamps, fake loading, or extra evaluations.

`src/components/demo/results-explorer.tsx` and its CSS module own the route-specific view. All content, model attribution, outcomes and provenance come from `RUN`; no dependency or data transport was added. Missing output displays as unavailable. The selector supports Tab/Enter, Escape and outside-click dismissal; the output tabs support arrow keys, Home and End. Evidence buttons support Enter/Space. Disclosures use short height/opacity transitions, output selection uses a short fade, and reduced motion disables both. Scroll anchoring is disabled for this view so expanding evidence does not move the reading position.
