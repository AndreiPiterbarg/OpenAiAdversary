The presentation closely follows figure 04 of [Linear's agent activity](https://linear.app/developers/aig): muted narration above a compact action row, small filled action symbols, inline metadata and a disclosure triangle, and a 6×6 animated dot-matrix working indicator. There are no numbered stage headers, connecting rails, agent badges, or session cards. Leading explanations stay visible as actions accumulate; opening an action reveals its code, comparisons, boundary notes or finding. CSS animates disclosures and newly arrived actions. The viewport follows newly arrived activity only in Follow live mode, after expansion settles. Reduced motion disables these transitions.

Typing uses elapsed time from [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame), so display refresh rate does not determine its speed. A [step-end caret animation](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/easing-function/steps) supplies the terminal cursor; no animation dependency is needed.

## Results

The user selected Sentry’s issue-detail hierarchy in dark mode, followed by the mirrored ranked bars in `frontend/docs/research/results-overview-research.md`. `/demo/results` opens on an unboxed distribution of outcomes under attack. Failures extend left from the central divider and successes extend right; each side ranks its categories independently. Both use the same solid bar, with muted warm and green colors, explicit outcome labels, and different icons. The page reuses the current typography, shell, separators, and compact spacing.

The overview initially shows the top three modes per outcome. An icon-only chevron below the lists expands to all modes and returns to the top three. It is centered on the vertical divider, rotates when expanded, and has accessible Show more modes / Show fewer modes labels. Expansion animates the extra rows and persists while inspecting examples, so returning from a lower-ranked mode restores that mode’s button. With the current three modes, the chevron is disabled. The mode count remains available to screen readers; the footer has no visible text.

Counts come from the available attacked-run examples, grouped by outcome and primary mode. Passing controls and unavailable follow-up checks never count as successes. Success means completing the task despite an attack. The three current fixtures are failures in three different modes, so each bar has a count of one and the same length. The success side explicitly has no supplied examples. Both sides share a count scale; these examples do not imply a model-wide rate or a benchmark denominator.

Selecting a bar carries its category label into a contextual heading and reveals only that mode’s examples, using a short direction-aware transition. The Sentry detail view remains hidden until a category is selected. All modes returns to the distribution and restores the selected bar’s keyboard focus and the overview’s scroll position. The Examples menu, adjacent-example arrows, and related examples stay within the selected mode; arrows are disabled at either boundary. Each current mode contains one example.

An unboxed issue header and compact toolbar flow into an event-detail panel and a separated context sidebar. Borders are reserved for evidence and internal separators. Each detail explains the task and changed condition. Primary explanations use 14px text with a 24px line height; supporting text uses 13px with 22–23px line height. Evidence sections, source rows, and metadata have more space between them. Controls, surfaces, borders, focus outlines, and code keywords use neutral grays; muted warm and green colors identify outcomes. Without attack / With attack tabs retain both outcome summaries and show the selected arm’s full observed output in one wide code frame. The attacked arm is selected initially, including for future success examples. Repository context and attack code expand independently as grouped source frames, with line numbers, restrained token colors, and pass/fail line highlights. Jump links open the relevant evidence section. A narrow metadata column identifies the models, unavailable follow-up checks, and the supplied mechanism.

`src/components/demo/results-overview.tsx` renders the distributions. `src/lib/demo/results.ts` groups and ranks `RUN.cases` using each case’s `mode` and explicit `perturbed.outcome`. Recorded examples can replace the fixtures in `src/lib/demo/run-data.ts`; the monitor’s paired comparison also derives its outcomes from these fields. `src/components/demo/results-explorer.tsx` and its CSS module own mode selection and evidence inspection. No new dependency or data transport was added; transitions use the installed Motion package.

The selector supports Tab/Enter, Escape, and outside-click dismissal; output tabs support arrow keys, Home, and End. Evidence buttons support Enter/Space.
