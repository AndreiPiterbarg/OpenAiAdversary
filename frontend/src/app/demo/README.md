# Live monitor
Run `npm run dev`, then open `/demo` (also linked from Projects).
Three distinct proxy cases run in sequence, each with five sections; no backend calls are made.
The opening explanation describes how repository history seeds attacks and how paired tests reveal failures. The activity feed and clock start only when the user presses Launch; time spent reading the introduction does not advance the run. The explanation remains above the activity afterward. Compact action symbols identify search, attack code, a paired test, follow-up checks, and the finding. Each case states the coding task, the change, and its consequence with brief narration; comparison columns are labeled “Without attack” and “With attack.” Displayed code is a minimal excerpt, not a complete backend integration. Follow-up checks without evidence say “No result yet.”
Explanations, source context, and the final finding appear immediately. Generated code types character by character with an inline caret, at 90% of the previous speed. Verdicts arrive as complete updates. Action duration follows the amount of streamed output. Thinking pauses and static reading beats are 25% longer: output starts after 312.5ms and remains for 812.5ms after the final character, with the thinking square visible through that pause. Static source context and findings retain a brief initial thinking cue. Timing is defined in `stepTiming` in `src/lib/demo/replay.ts`.
Cases arrive chronologically in an agent activity feed. Each entry expands into the same five-stage trace; the small counter derives its total from the data. There are no previous/next buttons. Future cases and actions are not shown before they start. Following live opens the current session and action, collapsing the previous one. Selecting or collapsing a session, or choosing an action, preserves the reader's place while execution continues and new entries arrive below. Reopening a completed case shows its finding first, with all earlier evidence available in the action rows. Follow live returns to the active case and action. The queue finishes without recycling old cases under new numbers.
Reduced motion resolves output without stopping the clock; hidden tabs catch up when visible again.
The recorded finding stays open for 4.5 seconds before the next case begins.
Replace proxy content in `src/lib/demo/run-data.ts`; each entry in `RUN.cases` supplies its change surface, evidence, and steps. Presentation timing adapts to that content. There is no documentation-only restriction in the view.
All current evidence is illustrative, including model-attributed program and response excerpts.
The presentation intentionally looks live; explain the simulation outside this screen. No timer or playback controls are shown.
A fixed Results link is visible at bottom right immediately, including before Launch. It opens `/demo/results` at any point without waiting for the monitor. That route currently contains only a heading and a return link inside the shared shell; the interactive explorer is the next phase. See `frontend/prompts/P-RESULTS.md` for the research-first handoff. Returning to `/demo` opens its Launch screen; playback state is not persisted across route changes.
Run `npm run test:demo`, `npm run lint`, and `npm run build` to verify changes.

The presentation closely follows figure 04 of [Linear's agent activity](https://linear.app/developers/aig): muted narration above a compact action row, small filled action symbols, inline metadata and a disclosure triangle, and a 6×6 animated dot-matrix working indicator. There are no numbered stage headers, connecting rails, agent badges, or session cards. Leading explanations stay visible as actions accumulate; opening an action reveals its code, comparisons, boundary notes or finding. CSS animates disclosures and newly arrived actions. The viewport follows newly arrived activity only in Follow live mode, after expansion settles. Reduced motion disables these transitions.

Typing uses elapsed time from [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame), so display refresh rate does not determine its speed. A [step-end caret animation](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/easing-function/steps) supplies the terminal cursor; no animation dependency is needed.
