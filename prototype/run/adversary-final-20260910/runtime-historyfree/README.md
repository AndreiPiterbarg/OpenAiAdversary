# History-free host runtime repair

The three successor repositories preserve the prepared task file bytes and modes, but replace the inherited Git object databases with fresh single-commit snapshots. Every stored object is reachable from that sole root commit. No source remotes, alternate object stores, or unreachable objects remain. Original benchmark commit identifiers are external metadata rather than accessible history.

Each task directory contains its new runtime pin, prepared reference, snapshot receipt, exact frozen baseline/gold compatibility results, and external-file access checks. Compatibility preserved the required 2 Factory Boy, 15 Asgiref, and 68 Djpress test outcomes; the trusted gold repairs passed. Dedicated virtual environments remain unchanged. Guarded commands cannot read the old runtime pins, controller source, or frozen proposer artifact. The known future Asgiref repair object is absent.

`future-history-audit.json` and `prior-arm-assessment.json` retain the earlier-arm integrity finding. Those arms are contaminated historical diagnostics, not clean benchmark or calibration evidence. Known-fix visibility counts are lower bounds; absence of that particular hash does not prove an episode was clean.

`source-receipt.json` identifies both the executed preparation script and the current source module. The current module also refuses nested Git metadata. These host runtime receipts do not establish generic protected test execution or a confirmed adversarial mode.
